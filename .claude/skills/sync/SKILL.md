# Sync — planning decision checkpoint

The user may feel overwhelmed with the back-and-forth and has lost the thread of their own decisions and what they still need to decide before we are in perfect harmony and we can start implementing the plan. Your job is to hand it back to them, compressed.

Report back to the user every point you asked them to make a decision on. This only applies to our current running plan. Do not restate decisions made that affected changes you have _already made_ this session - those are complete, move on mentally.

For all points that the user has already given their answer to, briefly state their choice.

For all points that are still pending, restate the original issue that arose the need for a decision on it, along with the original options, recommendations, and rough net lines you gave. These may be as detailed as you originally presented them. They may have changed, as the back-and-forth may have provided additional insight into the original issues that reframes either the options, or your genuine _correct_ recommendation. Or, there may be new issues altogether that also require a decision from them.

For all small items that didn't require a decision from the user, but which the correct option for was unambiguously obvious, _do not_ regurgitate your choice back. Only bother the user with the things requiring their input.

Number the blocks so the user can reply easily.

If the user has already provided their choice on all items you needed a decision on, don't fabricate new ones for the sake of having something. Only present new items if you genuinely think they are large enough to require a decision from the user. Otherwise, ask for the go-ahead to implement the plan. Do not start making changes without explicit approval.

Remember to follow your output style.
